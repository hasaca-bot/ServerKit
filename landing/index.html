From commit to traffic, with a way back

Every deploy starts the new version beside the old one and only moves traffic once it answers its health check.

  1. Connect your repository

    Install the GitHub app on the repositories you choose. You can deploy only what that connection grants.

  2. Push to deploy

    Each push to your branch builds and releases automatically. Add [skip deploy] to a commit message to skip one.

  3. Review in a preview

    Every pull request gets its own environment and URL, removed when the PR closes.

  4. Roll back in one click

    Failed health check? The live version stays up. Shipped a bug? Return to any earlier deploy.

  • Zero-downtime deploysHealth-checked switch-over, no dropped requests.
  • Env vars and secret groupsShare a group across services; secret values stay hidden.
  • Logs and metricsLive logs, CPU and memory per service.
  • Custom domainsPoint your domain, get a certificate automatically.

The safety model

  • Per-user keysEach key belongs to one person, can be named per assistant, and can be revoked at any time.
  • Scoped to your own resourcesOther accounts' apps do not exist as far as your key is concerned. Deploys only come from repositories your GitHub connection grants.
  • No secret values returnedTools list environment variable names, never values, so a prompt injection cannot read them back.
  • Same limits as the dashboardPlan quotas and roles apply to every call an assistant makes.

Add it to your assistant with one URL: https://app.example.com/api/v1/mcp

Questions

Which repositories can I deploy?

Repositories your own GitHub connection grants access to. You never paste another account's repository URL, and the same rule applies to the MCP endpoint.

What can an AI assistant do with my key, and what can't it?

It can use the tools the endpoint exposes, such as publishing sites, reading logs, rolling back and managing databases, on your own resources. It cannot see other accounts, read secret values, or exceed your plan limits.

What is the difference between app hosting and an AI-managed VPS?

App hosting runs your code for you: push, and it is live, with databases, previews and rollbacks. An AI-managed VPS is a whole server that you operate through your assistant, for workloads that need full control of the machine.

Is it open source?

The core is open source under the MIT License, based on ServerKit by Juan Denis. You can read the code and run it yourself; the hosted service adds plans, billing and managed infrastructure.

Do the prices include VAT?

No. All prices are in USD and exclude VAT, which is added at checkout where it applies.
